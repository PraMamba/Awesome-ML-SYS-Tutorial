# LLM Backbone + RVQ 多码本自回归生成：跨领域迁移设计笔记

> 一套把 **LLM backbone 当作「多码本 RVQ 离散序列」自回归生成器**的设计范式，抽象成**领域无关**的框架 + 迁移检查清单。
>
> 适用对象：任何「先把连续信号用（残差）向量量化成离散 token 网格，再用一个自回归 LLM 生成该网格」的模态 —— 语音、音乐 / 通用音频、图像、视频、动作 / 传感器时序……
>
> 本文只讲**与模态无关的核心设计**：码本几何、残差顺序约束、四种生成策略、两类回避方案、解码回信号的完整链路、以及迁移要点。范式的一个成熟实例是语音 TTS，本文机制正是从若干 TTS 系统提炼而来；需要具体锚点（模型、数字、图示）时见[文末「出处」](#6-术语表--出处)。正文只在少数几处用一行脚注点到语音实例。

---

## 0. 一句话抽象与数据流

> **连续信号 → 用 (R)VQ 量化成 `[T, N]` 的离散码本网格 → 一个 LLM backbone 自回归地生成这张网格 → 再解码回连续信号。**

- `T` = 序列步数（有多少个「帧」）
- `N` = 码本层数（每个帧要用几个离散 token 才能描述）

数据流分四段，其中**只有第 ③ 段是 LLM backbone**，但它吃掉绝大部分算力，也是本文核心：

| 段 | 职责 | 输入 / 输出 |
|---|---|---|
| ① 预处理 | 载入条件输入（IO-bound，通常无 GPU） | 原始条件 → 张量 |
| ② 编码器 | 把条件信号**降采样并量化**成低帧率的码本网格 | 连续信号 → `[T, N]` 码 |
| ③ **LLM backbone** | **自回归生成 `[T, N]` 码本网格**（本文主体） | 条件 → 逐帧多码本 token |
| ④ 解码器 | 把生成的码本网格解回连续信号（详见 §3） | `[T, N]` 码 → 连续信号 |

② 与 ④ 常常是同一个「tokenizer」模型的两个方向（编码 = 信号→码，解码 = 码→信号），但也可以是两个独立模型 —— 这个选择直接影响显存与部署（见 §4.1-⑧）。

## 1. 通用原语（Codec token / Codebook / RVQ layer）

### 1.1 可视化坐标系：`step × codebook` 网格

先立一个坐标系：**横轴是自回归 decode step，纵轴是 codebook（即量化层）**，每个格子是「在某一步、为某一层采样出的一个离散 token」。特殊格子（帧边界标记）不携带真正的信号内容。整个生成过程就是这张网格**从左向右逐列延伸**。后面各种策略的差别，本质就是「同一帧的 N 个 token 在这张网格里怎么摆」。

### 1.2 Codec token

普通 LLM 消费的是「有限词表里的离散 token ID」。要让 LLM 也能生成连续信号，就得给信号一套同样的接口：

> **一个 codec token = 一个整数 ID，代表一小片信号。**

接口上它和文本 token 完全一致（都是查一张 embedding 表的整数索引），差别只在于它代表的是「一小段信号」而非一个词。

### 1.3 Codebook

> **一个 codebook = 某一量化层的静态词表**：一组候选码字（每个是一个 ID），每个 ID 映射到一个 embedding 向量。

- 每层码本规模有限（候选码字数量典型在 `10³–10⁴` 量级）。
- **务必分清两个「大小」**：码本大小（候选码字**个数**，决定每个输出 head 的分类维度）≠ 生成序列长度 `T`（帧数，决定 AR 要跑多少步）。二者常被混淆。
- 在网格里：**每个 codec token 是一个格子，每个量化层是一行，每行共享同一个 codebook。**

### 1.4 RVQ layer 与「残差顺序约束」（迁移时最需要吃透的一节）

**RVQ = Residual Vector Quantization**（残差向量量化，[Zeghidour et al., 2021](https://arxiv.org/abs/2107.03312)）。把一帧信号只量化成单个整数 ID 太粗糙。RVQ 把多个量化层**串成残差链**：

- `L₀` 先量化**粗糙信号**；
- `L₁` 量化 `L₀` 留下的**残差**；
- `L₂` 量化 `L₁` 还没补上的部分；……每层捕捉越来越细的细节；
- **解码 = 把所有层的贡献相加**，重建出信号。

> **一个 RVQ layer = 拥有一个 codebook 的一个残差量化层。** N 层意味着「每个对齐后的信号单元（帧）最终需要 N 个采样出的 ID，每层一个」。

**层间语义不对称**（迁移时要映射到你的模态）：

| 层 | 编码内容（一般化） |
|---|---|
| `L₀`（粗层） | 信号的**粗结构 / 全局骨架 / 语义主干** —— 丢了往往等于丢内容 |
| 深层（`L₁…`） | **细节 / 纹理 / 高频残差 / 精化** —— 丢了更多只是质量下降 |

**为什么这一节对迁移最关键？** 残差机制引出一个**硬约束**：

> **RVQ 的层级残差机制，让「生成同一帧不同层 token 的顺序」变得重要。**

- 层 `i` 量化的是层 `<i` 剩下的残差 → **同一帧内，层 `i` 的取值在条件上依赖于层 `0…i-1`**。
- 若一帧的 N 层在同一时刻、从同一次 forward 里**独立并行采样**，高层看不到低层刚采出的 token → 残差链断 → 重建质量下降。
- 若严格逐层顺序采样，质量好，但延迟随层数近似线性放大。

**这个「并行的速度 vs. 顺序的残差保真」trade-off，就是后面全部生成策略要解决的核心问题。**

> **移植前第一问**：你的量化器是**单层 VQ** 还是**多层 RVQ**？若单层 VQ（无残差层级），层内顺序无所谓，**直接并行即可，本文 §2.3 / §2.4 都不必要**。以下全部内容只在多层 RVQ（或任何有层间依赖的多码本量化）时才有意义。

### 1.5 帧 = `[1, N]` 竖列（可解码的形状）

一帧信号被编码成一个「codec token 列表」，长度 = 层数 N。习惯竖放，所以**一帧形状是 `[1, N]`**，整段信号是 `[T, N]`。

- **喂给解码器时，一帧必须在网格上排成一竖列 `[1, N]`**（同列的 N 个 token 描述同一个信号时间步）。这就是「可解码 / decoder-ready」。
- 但在**生成过程中**，同一帧的 N 个 token 不一定排成竖列 —— 有的策略会把它摊成对角线，之后再搬回竖列（§2.3）。

### 1.6 step vs. 帧；N 个 head；embedding 求和反馈

- **帧**：信号的一个对齐单位；一段信号有 `T` 个帧。
- **step**：自回归的一步。粗略地说，**每个 step，backbone 前向一次、产出一个 hidden state**；然后每个活跃的量化层各有一个 **output head**，从这个 hidden state 投影到自己那张 codebook 的分布上，各采一个 ID。**一个 step 最多写入 N 个 ID。**
  - 这和普通 LLM「一个 LM head 从 hidden state 采一个 token」是同一回事 —— 只不过这里要用 **N 个 head** 才能凑齐一整帧的 `[1, N]`。
- **关键反馈回路（迁移必抄）**：一个 step 采出的 N 个 token，其 **embedding 会被求和成一个向量**，作为 backbone 下一步的输入。多码本 → 单输入向量，靠的就是 embedding 求和。

## 2. 核心张力与四种生成策略（本范式的真正内核）

### 2.1 中心 trade-off

在「每个 step 怎么产出一帧的 N 个层」上有一条连续谱：

- **一个极端 —— 全并行**：一次 forward 同时采完 N 层。最快，但破坏残差条件。
- **另一个极端 —— 全顺序**：每层各跑一次完整 backbone forward。保真，但延迟 ~N×。

四种策略是这条谱上的不同取点：

### 2.2 四策略对照

| 策略 | 某个 step 发生了什么 | 质量 / 速度 |
|---|---|---|
| **Parallel（全并行）** | 全部 N 层同时从同一个 hidden state 采真实 token | 快（1 forward/帧），但 `Lᵢ` 看不到 `Lᵢ₋₁` → 残差链断 |
| **Sequential（全顺序）** | 从 `L₀` 到 `L_{N-1}` 逐个填满一帧，每层一次完整 forward | 保残差，但延迟 ~N× |
| **Staggered（delay pattern）** | 所有层共享一次 per-step forward，但各层**错开激活**，同一 step 采的 token 属于**不同帧** | 近并行速度 + 因果的跨层条件 |
| **Backbone + Inner Module** | 大 backbone 提供每帧时序上下文；小 inner 模型顺序填满每帧的 N 层 | 每帧保持竖列、即刻可解码；把码本级循环搬到廉价模型 |

后两种是工程上真正用的「聪明解」，下面分别深挖。

### 2.3 Delay Pattern（错位激活）

**核心思想**：所有层共享同一条 step 轴、也共享**同一次 per-step backbone forward**；靠**错位激活**在近并行速度下拿回残差条件。

用一张 `N=4` 的通用网格对比（`fₖ` = 第 `k` 帧在该层的 token；`BOC` = 帧边界占位符；`—` = 已结束）：

```
Non-delay：每帧 = 一竖列（decoder-ready）
        step0 step1 step2 step3 ...
  L0      f0    f1    f2    f3
  L1      f0    f1    f2    f3
  L2      f0    f1    f2    f3
  L3      f0    f1    f2    f3
          └f0   └f1   └f2   └f3      ← 每列就是一帧

Delay：每帧 = 一条对角线（生成后需 undelay 搬回竖列）
        step0 step1 step2 step3 step4 step5 ...
  L0      f0    f1    f2    f3    f4    f5
  L1     BOC    f0    f1    f2    f3    f4
  L2     BOC   BOC    f0    f1    f2    f3
  L3     BOC   BOC   BOC    f0    f1    f2
          ↘ 帧 f0 = 对角线 {L0@0, L1@1, L2@2, L3@3}
```

**机制**：

1. **错位激活（ramp-up）**：第 `i` 层比第 0 层晚 `i` 步才开始真正采样；激活前用 **BOC（帧边界占位符）**填格 → 网格左下角是一片 BOC 三角。
2. **对角线即一帧**：帧 `k` 落在 `{L₀[k], L₁[k+1], …, L_{N-1}[k+N-1]}`。
3. **undelay**：把对角线移回来 → 变成对齐后 `[T, N]` 网格的第 `k` 列（竖列）→ 可解码。
4. **为什么残差条件成立**（精髓）：当第 `i` 层在 step `k+i` 采样帧 `k` 时，**同一帧的第 `i-1` 层已在上一步 `k+i-1` 采过了**；backbone 的 KV cache 累积了 `k…k+i-1` 步的历史，已把低层 token 编码进注意力上下文。于是「层 `i` 依赖层 `<i`」这个残差要求，靠**共享 backbone 的因果注意力**自动满足，**无需 N 次独立 forward**。
5. **wind-down**：与 ramp-up 对称。当 `L₀` 发出 **EOC（序列结束标记）**后，更高层还要各自再跑，把尾部帧补完。

**代价**：为得到 `T` 帧，delay pattern 恰好多花 **N 个额外 step**（ramp-up + wind-down 合计，即把网格「剪」成对角线所需的额外列）。当 `T ≫ N` 时开销可忽略（例如 `T=250, N=8` → ~3%）。换来**逼近并行的速度 + 优于并行的质量**。

> **迁移要点**：delay pattern 是纯粹的**调度技巧**，与模态无关。你需要为你的模态定义：BOC/EOC 的等价物（帧边界标记，非内容）、N 的取值（决定 ramp-up/wind-down 百分比与**解码启动延迟**：解码器至少要等齐 N 行才能 undelay 出第一帧）。

### 2.4 Backbone + Inner Module（保持竖列）

**核心思想**：不把一帧摊到对角线，而是让**每帧在网格上保持一竖列**。一个**大 backbone** 沿时间轴推进（每帧一次前向、提供时序上下文），一个**更小的 inner module** 沿码本深度填满每帧余下的层。每帧一生成出来就是可解码的，不需要 delay/undelay。

关键点：**每帧内部仍有一个对码本的顺序内层循环**（保住残差层级），但它跑在一个**小得多的模块**里，而不是为每层调用一次完整 backbone —— 既保残差，又不付 N× 的 backbone 成本。

这一类里有两种变体，**唯一的结构差别是「粗层 `L₀` 在哪里被采样」**：

- **变体 A —— backbone 自己采 `L₀`**：大 backbone 逐帧采样粗糙的 `L₀`（语义层），把自己**最后一层 hidden state + 采出的 `L₀` embedding** 交给一个独立的小 AR 模型，由后者顺序生成剩余层 `{L₁, …, L_{N-1}}`（细节层）。相当于**两个模型分工：一个管语义、一个管细节**。小模型通常参数少、层浅，且其 KV cache 每帧重建。
- **变体 B —— backbone 不采样任何 token**：大 backbone **只产出 hidden state**，自己不采样；用它当**种子输入**喂给一个极小的 inner 模型，由 inner **顺序采出该帧的全部 N 层（含 `L₀`）**，每步采一个、feedback 给下一步。相当于**一个模型只负责时序上下文，另一个模型才实际生成每帧的全部 token**。

> **易混点（迁移时最容易踩）**：A、B **唯一的区别就是 `L₀` 在 backbone 采还是在 inner 采**。二者常被张冠李戴 —— 「backbone 采 `L₀`、inner 补其余」是 A 的特征，别把它安到 B 头上。设计 / 复现时先明确这一条。<br>*（语音实例：A = Fish Audio S2-Pro 的 Dual-AR；B = MOSS 的 Global+Local。）*

**serving 视角，两变体共享同一套调度**：每帧一次 backbone 前向 + inner 里一个顺序码本循环 + 没有 delay/undelay，而且这个 inner loop 可被整体 capture 成一张 CUDA Graph。

### 2.5 两条路的收束

**delay pattern** 与 **backbone + inner** 是**规避残差 trade-off 的两种正交思路**：

- **delay pattern**：把一帧摊成**对角线**、用错位激活 + 共享 backbone 的 KV 拿回残差条件，之后 undelay；额外付 ~N 步。
- **backbone + inner**：让每帧保持**竖列**，把码本级生成搬进一个**更廉价的 inner 模型**；额外付一个小模型的成本。

## 3. 从码本网格解码回信号（RVQ token decode）

到这里，§2 的策略已经把完整的 `[T, N]` 码本网格生成了出来；而 §1.4 早埋下一句话 —— 「解码 = 把所有层的贡献相加」。这一节把它展开成完整链路。解码是**编码的严格镜像**：编码把连续信号「降采样 + 逐层残差量化」压成离散码，解码就沿原路「逐层码字相加 + 上采样」还原回信号。它接在 backbone 之后、本身通常不含自回归，计算比 backbone 轻；但「残差顺序约束」和「delay pattern」欠下的几笔账，恰恰要在这里结清。

对着 §1.1 那张 `step × codebook` 网格，整个过程分三步。

**第一步 · 取齐一帧的竖列。** 解码的最小单位是一帧，也就是一整条 `[1, N]` 竖列 —— N 层必须**同时到齐**：每层只是这帧信号的一部分残差，缺任何一层，求和就不完整。由此有两个前置动作：

- **undelay（仅 delay pattern 需要）**：生成时一帧被摊在对角线 `{L₀[k], L₁[k+1], …}` 上（§2.3），得先把对角线搬回竖列，才能凑齐这帧的 N 个码。这也正是 delay pattern 启动延迟的来源 —— 解码器至少要等到第 N 行出现，才 undelay 得出第一帧。non-delay 策略生成出来就是竖列，跳过此步。
- **清洗特殊 token**：帧边界标记（BOC/EOC）不是真实码字，混进来会索引到无意义的 embedding；解码前要把它们剔除、或 clamp 回合法码字区间。

**第二步 · 查表 + 残差求和 → 每帧潜变量（RVQ 逆运算的核心）。** 对帧 `k` 的每一层 `i`，用它的 token ID 去第 `i` 层的 codebook 查出码字向量 `eᵢ`，再把 N 层码字**相加**：

```
z_k = e₀ + e₁ + … + e_{N-1}
```

`z_k` 就是这帧重建出的**连续潜变量**，是原始（量化前）潜变量在这套码本下的最近似。「为什么是相加」正对应 §1.4 的残差链：`L₀` 给出粗略近似，`L₁` 补上第一层残差，`L₂` 再补，逐层叠加即拼回完整潜变量。

> **顺带得到一个好性质 —— 优雅降级。** 因为是逐层相加、且靠前的层承载更粗更关键的结构（§1.4 的层间不对称），只加前 `M < N` 层仍是一个合法、只是更粗糙的重建。这是带宽 / 算力受限时的天然质量旋钮，也是 RVQ 胜过单层 VQ 之处，迁移时值得利用。

**第三步 · 上采样回连续信号。** 把逐帧潜变量按时间拼成低帧率序列 `[T, D]`（D = 潜变量维度），交给解码器网络做**上采样**，还原成全帧率的连续信号 —— 正是编码器降采样的逆操作。解码器形态跟随编码器：卷积式编码 ↔ 转置卷积 / 上采样式解码，纯 transformer 编码 ↔ patch 展开式解码。

三步走完，§0 承诺的来回路径就闭合了：

```
连续信号 ──编码──▶ [T,N] 码 ──backbone 生成──▶ [T,N] 码 ──查表+逐层求和──▶ [T,D] 潜变量 ──上采样──▶ 连续信号
```

**一个绕不开的收尾 —— 跨帧连续性。** 第三步的解码器网络有跨越多帧的感受野 / 内部状态，所以**解码不是逐帧独立的**，相邻帧共享上下文。这逼出一个迁移前必须想清的岔路：解码器若能**跨帧维持连续内部状态**，就能真正逐帧 streaming、无缝输出；若不能（如卷积状态在块边界被打断），就得靠 windowed chunking（累积一窗、回看 overlap、crossfade、holdback 未完成的尾帧）消除边界 artifact —— 这笔属于 serving 层的账，详见 §4.2-④。

## 4. 迁移到新领域：检查清单

### 4.1 建模决策（移植前必答）

1. **你的「帧」是什么？** —— 可被量化、且能被解码回一小段输出的**对齐单位**。**帧率 × 时长 = `T`（序列长度）**，直接决定 AR 步数与成本。
2. **量化器是单层 VQ 还是多层 RVQ？** —— 单层（无残差层级）→ 层内无序 → **直接并行**，§2.3/§2.4 都不必要；多层 → 层内有序 → 必须在四策略里选。
3. **N（层数）与码本大小？** —— N 决定每帧采几个 token、delay 的 +N 开销与启动延迟；码本大小决定每个 head 的输出维度。
4. **coarse-to-fine 语义怎么分布？** —— `L₀` 编码你信号的什么「粗结构 / 语义」？它是否**强到值得让大 backbone 直接建模**？是 → 倾向**变体 A**（backbone 采 `L₀`）；各层较同质 → **变体 B** 更简洁。
5. **选哪种生成策略？**

   | 你的诉求 | 选 |
   |---|---|
   | 最简单、层间弱依赖（或单层 VQ） | Parallel |
   | 质量优先、延迟不敏感 | Sequential |
   | 要并行速度 + 因果层间条件，能接受 undelay 逻辑与 +N 步 | **Delay pattern** |
   | 要每帧即刻可解码，愿意加一个小 inner 模型 | **Backbone + Inner**（再在 A / B 二选一） |

6. **若走 delay pattern**：定义 BOC/EOC 等价物；算清 +N 步占 `T` 的百分比；注意解码器**至少要等齐 N 行**才能出第一帧（启动延迟）。
7. **若走 backbone + inner**：决定 `L₀` 在哪采（A vs B）；定 inner 模型规模（层数 / 是否每帧重建 KV）；确认「N 个 token embedding 求和后 feedback 给 backbone 下一步」这条回路。
8. **tokenizer 是双向同模型，还是编 / 解两套？** —— 同一模型双向 → 额外权重 ≈ 0；两套独立模型 → 额外显存可观，且需**单独部署解码器实例**。决定显存预算与部署形态。

### 4.2 设计诱发的系统级坑（迁移时必须一并搬过去）

1. **神经量化器的 batch-size 数值漂移**（最隐蔽，对 RL / 缓存致命）：改变 encode 的 batch size → 改变底层 GEMM 的形状（M 维）→ 数值库（如 cuBLAS）选到不同 kernel → 浮点累加顺序变 → sub-ULP 漂移。这点漂移本不可见，但**硬量化紧跟其后**：靠近码字边界的帧，哪怕 1 bit 扰动都会 snap 到相邻码字 → **离散 token 翻转**（在神经 codec 上实测可达数个百分点）。后果：`encode(A) ≠ encode([A, B])[0]` → **batched 编码缓存不安全**，以及**神经（相对符号）tokenizer 独有的一种训练-推理 skew**。→ 做 RL 或做 encode 缓存时，务必固定 batch 或严格按单条 encode。
2. **静态执行路径 vs. 动态状态机**（想上 CUDA Graph 就绕不开）：delay pattern 的每请求状态（层 offset、EOC 倒计时、done flag）若写成分支式 `if/else`，就无法被 CUDA Graph capture，必须改写成**原地 tensor 操作 + 固定地址 shadow buffer**；backbone+inner 的每帧 micro-loop（1 次 backbone + N 次 inner）同样要**压平成无条件分支的一张图**。
3. **顺序内层循环 → kernel launch 密集**：backbone+inner（尤其变体 B 的 `1 + N` micro-step）每帧发起大量小 kernel，launch 开销累积；eager 路径常表现为「每帧耗时与 batch size 无关」的 launch-bound 信号 → 需要把整个 micro-loop capture 成一张图。
4. **streaming 取决于解码器状态是否跨帧连续**：解码器天生**逐帧 streaming**（跨帧维持连续内部状态）→ 无拼接 artifact；解码器**不可 streaming**（如卷积状态在块边界被打断）→ 需一整套 **windowed chunking**：stride 累积 + overlap 回看 + crossfade + **holdback**（保留高层码本仍不完整的尾帧）。delay pattern 还叠加一个启动成本：至少要 N 行才能 undelay 出第一帧。

## 5. 迁移速查

- **先判量化器类型**：单层 VQ → 直接并行，收工；多层 RVQ / 有层间依赖 → 往下。
- **再选生成策略**：延迟不敏感→Sequential；要速度+质量→Delay pattern 或 Backbone+Inner。
- **Backbone+Inner 二选一**：`L₀` 值得大模型直接建模→变体 A；否则→变体 B。别把两者的 `L₀` 采样位置搞混。
- **抄三条通用机制**：① N 个 token embedding 求和回喂 backbone；② delay 靠共享 KV 的因果注意力拿回残差条件；③ inner micro-loop / delay 状态机都要静态化才能上 CUDA Graph。
- **别忘四个系统坑**：batch 量化漂移、静态执行路径、kernel launch、streaming 依赖解码器跨帧状态。

## 6. 术语表 / 出处

**通用术语**

| 术语 | 含义 |
|---|---|
| codec token | 代表一小片连续信号的整数 ID（`[1,N]` 里的一个格子） |
| codebook | 某一量化层的静态离散词表（一组码字 → embedding） |
| RVQ layer | 残差量化层；第 `i` 层量化前 `i` 层的残差 |
| 帧 / frame | 信号的对齐量化单位，形状 `[1, N]` |
| 编码器 / 解码器 | 信号 ↔ `[T,N]` 码 的两个方向 |
| delay pattern | 错位激活的多码本近并行生成 |
| BOC / EOC | 帧边界 / 序列结束标记（非内容） |
| backbone + inner | 大模型管时序 + 小模型沿码本深度填帧 |
